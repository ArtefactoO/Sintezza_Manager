# Forever addon manager

The agreed design and interactive mock-up are recorded in the workspace verification artifacts under `manager-mockups-20261120`. The client target is WoW Forever 1.60.1.70959, TOC interface 16001. [Source pin](https://github.com/Gethe/wow-ui-source/tree/3d8abb1da73acd38e412e24fb3f99454a6392346)

| Requirement | Acceptance | Implementation |
| --- | --- | --- |
| REQ-01 — Inventory | The All filter is active on first opening. State filters choose which groups and standalone addons appear. Expanded groups show all modules within the search and category, with disabled counts out of the total. Installed suites such as EllesmereUI appear once with modules beneath them. Required dependencies are listed in the tooltip. | Core.lua, Window.lua |
| REQ-02 — Apply | Checkboxes stage changes. Enable required dependencies and account for dependents when disabling. Preview each affected addon, confirm for the current character, then save and reload. Guard combat, missing dependencies, and a stale inventory. | Core.lua, Window.lua |
| REQ-03 — Profiles | Select, load and save account-wide sets manually from the AddOns tab. Loading stages a draft and confirms replacement of differing edits. The Profiles tab shows saved contents. Existing saved sets survive the removal of automatic character links. | Core.lua, Window.lua, Launcher.lua |
| REQ-04 — Entry points | Open from the built-in AddOns button in the game menu, one Settings category, or `/smanager`. Redirect the button after the menu rebuilds when addon management is available outside combat. | Launcher.lua |
| REQ-05 — Appearance | Use a compact table with distinct on, off and pending states. Provide 28-pixel addon rows and larger checkbox and disclosure targets. Reuse the shared Theme row bands, hover, checkbox and disclosure styles when available. Show the icon and version in both modes. Provide English and Russian with an English fallback. | Locale.lua, Style.lua, Window.lua, Media/Icon.tga |
| REQ-07 — Window size | Resize from the bottom-right grip down to 480 UI pixels wide and persist the dimensions. Keep the toolbar and dialogs usable at minimum width. Reset from the addon settings page. Follow the Theme global window scale, opacity and layer, with a per-addon scale override. Provide native resize and reset without Theme. | WindowSize.lua, Window.lua, Launcher.lua |
| REQ-08 — Group and profile actions | Remember collapsed groups, open matching branches during search, show module counts, and stage group changes as one dependency-checked action. Rename and duplicate saved profiles. | Core.lua, Window.lua |
| REQ-09 — Compact tabs and state | Show search beside category selection and put status filters below, with profile Load and Save actions in the header. Use Theme's picker for categories when available. Update checkboxes with draft changes and use an arrow in the status column to indicate the current and pending states. Expose profile contents and actions on a separate tab. | Window.lua, WindowSize.lua |
| REQ-10 — Outdated addons | Mark outdated rows and keep their character checkboxes available. Stage the game-wide loading option independently of the profile and apply it with the addon changes. | Core.lua, Window.lua |
| REQ-06 — Navigation | All actions are reachable by mouse. Category and dialog navigation use native mechanisms where available. The search and profile editor support keyboard input, and Escape dismisses the window or confirmation. Check controller focus from the game menu, list scrolling, selection, modal return, and text entry in the Forever client. | Style.lua, Window.lua, Launcher.lua |

## Implementation and verification

- REQ-01 through REQ-03 cover nested and missing dependencies, manual profile loads, character-scoped state changes, a stale inventory, combat, and rollback after either an enable-state write or a save failure.
- REQ-04 covers pooled game-menu buttons, the native combat fallback and disabled state, outside-combat launch, one-time Settings registration, and the slash command.
- REQ-05 passed Lua 5.1 tests for both languages in both modes, including Theme taking precedence and English fallback. The offline layout check exercised the disabled list and reload confirmation in four combinations. The evidence is under `manager-implementation-20261120`.
- REQ-06 has mouse and keyboard input paths in the implementation. Check in-game controller acquisition from the Esc menu, cursor or directional navigation, confirmation focus, and close. The outside-client checks do not establish controller support or exact in-game appearance.
- REQ-07 passed offline resize, minimum bounds, reset, and shared scale, opacity and layer checks using Theme's actual window-preference code. Layout evidence includes the minimum size in both languages and modes. Client resize behavior still needs in-game verification.
- REQ-08 covers restoration after clearing search, a failed dependency leaving the draft intact, and independent copied profile data. In-game context menus require a client check.
- REQ-03 and REQ-09 pass offline tests for legacy bindings being ignored, saved sets and unknown addon keys being preserved, manual loading on another character, both outcomes when replacing a draft, and separate AddOns and Profiles layouts. The layout fixtures exercise the compact and minimum sizes in both languages with and without Theme.
